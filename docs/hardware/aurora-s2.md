# Aurora S2 (Rongta) — паспортные данные

Взято с карточки производителя для серии **AURORA S2L / S2L-AI**
(<https://www.rongtatech.com/aurora-s2l-ai-scale_p111.html>). Это то, на что
опирается вёрстка киоска и параметры весоизмерительной части в коде.

> В каталоге Rongta есть S2, S2L, S2L-S, D2, DP01 — модели с индексом **S2D**
> на сайте нет. Если на столе окажется другая модификация (например, 15/30 кг
> с делением 5/10 г), правятся только переменные `S2L_SCALE_*` в `.env` —
> код не трогается.

## Экран

| Параметр | Значение |
| --- | --- |
| Диагональ | 15.6″ |
| Разрешение | **1920 × 1080**, ландшафт (проверено на самом приборе; в спецификациях вендора значилось 1366 × 768) |
| Тач | мультитач, ёмкостный |
| Второй экран | 15.6″, опция (экран покупателя); разрешение на приборе не проверялось |

Из этого следует вёрстка: сетка каталога по умолчанию **4 × 2**. Ограничение
осталось от замеров на 1366 × 768, где при трёх рядах карточка сжималась до 131 px
и фотография переставала читаться; на 1080 запас по высоте больше, и число рядов
можно поднимать настройкой. Клавиатура ограничена 38 vh — иначе при наборе от сетки
почти ничего не остаётся.

## Весоизмерительная часть

| Параметр | Значение |
| --- | --- |
| НПВ | 6/15 кг (есть исполнение 15/30 кг) |
| Цена деления | **2 г до 6 кг, 5 г выше** (для 15/30 кг — 5/10 г) |
| Наименьшая навеска | 40 г |
| Класс точности | III (OIML R76) |

Отсюда:

- показание всегда кратно цене деления — квантование в `FakeScale.read()`,
  реальная плата отдаёт уже квантованное значение;
- перегрузка объявляется выше НПВ + 9 делений;
- минимальная масса для печати по умолчанию 40 г, а не 5 г.

Эти параметры лежат в `backend/.env` (`S2L_SCALE_CAPACITY_G`,
`S2L_SCALE_DIVISION_G`, `S2L_SCALE_FINE_DIVISION_G`, `S2L_SCALE_FINE_RANGE_G`),
а **не** в админке: это свойства прибора, и оператор торговой точки менять их
не должен.

## Протокол весовой платы (подтверждён на приборе, issue #1)

| Параметр | Значение |
| --- | --- |
| Порт | `/dev/ttyS4` — встроенный RS232, не USB |
| Режим | 19200 бод, 8N1 |
| Кадр | 8 байт: обрамляющий байт + **6 ASCII-цифр массы в граммах** + обрамляющий байт |

Пример кадра: байт 0x02, затем текст `001240`, затем байт 0x03 — это 1240 г.

Что из этого следует для драйвера (`hal/scale/serial_scale.py`):

- кадры выцепляются из потока по признаку «шесть цифр между двумя нецифровыми
  байтами», а не отрезаются вслепую по 8 байт: после потери одного байта слепое
  чтение начинает склеивать половинки соседних кадров в правдоподобные, но
  неверные числа — на весах это неверная цена на этикетке;
- признак стабильности плата не передаёт, поэтому он вычисляется на стороне ПК:
  пять подряд отсчётов в пределах цены деления;
- назначение обрамляющих байтов не выяснено. Драйвер показывает их как есть в
  `/api/status` (`frame_prefix`, `frame_suffix`) — посмотрите там, что реально
  приходит, прежде чем закладываться на их смысл.

## Принтер этикеток

| Параметр | Значение |
| --- | --- |
| Тип | термопечать |
| Ширина ленты | **не более 56 мм** |
| Разрешение | 203 dpi (8 точек/мм) |
| Скорость | 90 мм/с |

Отсюда размер этикетки по умолчанию **56 × 40 мм** (было 60 × 40 — не влезало
в печатающий узел), а поле ширины в админке ограничено 56 мм. 203 dpi совпадает
с константой `DOTS_PER_MM = 8` в рендере.

## Вычислительная часть

| Параметр | Значение |
| --- | --- |
| CPU | Intel Elkhart Lake J6412, 2.0 ГГц |
| ОЗУ | 4/8/16 ГБ DDR4 |
| Штатная ОС | Windows 10/11 |
| Порты | 2 × USB 2.0, 2 × USB 3.0, RJ45, RS232, RJ11, DC |

x86_64 — Ubuntu 24.04 ставится штатно, как и планировалось. Догадка про **RS232**
подтвердилась: весовая плата висит именно на встроенном последовательном порту
(`/dev/ttyS4`), а не на USB.
