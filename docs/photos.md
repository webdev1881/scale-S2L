# Фотографии товаров

Снимки в `frontend/public/products/` — демонстрационные, их место займут ваши. Ниже
порядок замены: сначала быстрый способ для готового набора снимков, потом ручной — для
одной-двух карточек.

## Где лежат и как попадают на экран

| Что | Где |
| --- | --- |
| Файлы снимков | `frontend/public/products/` |
| Ссылка в базе | поле `image` товара — **только имя файла**, без пути |
| Адрес на экране | `/products/<имя файла>` |
| Обложка группы | фото первого товара в ней, отдельного набора картинок нет |

Прибор отдаёт снимки из собранного фронтенда (`frontend/dist/products/`), а туда они
попадают из `public/` **во время сборки**. Поэтому после добавления файлов обязательно:

```bash
cd frontend && npm run build
```

Без пересборки новый файл не появится, и карточка останется с эмодзи-заглушкой. (Если
такой порядок неудобен на работающем приборе — скажите, отдам каталог снимков напрямую,
тогда файлы будут подхватываться без сборки.)

## Быстрый способ: весь набор сразу

1. Удалите демонстрационные файлы и `credits.md`:

   ```bash
   rm frontend/public/products/*
   ```

2. Назовите свои снимки **кодом товара**: `101.jpg`, `102.jpg`, `205.jpg`. Код — то же
   число, что покупатель набирает кнопкой «за Кодом», оно видно в админке в колонке
   «Код». Годятся `.jpg`, `.jpeg`, `.png`, `.webp`.
3. Сложите их в `frontend/public/products/` и пересоберите фронтенд:

   ```bash
   cd frontend && npm run build
   ```

4. Привяжите снимки к товарам одной командой:

   ```bash
   cd backend && .venv/Scripts/python tools/link_photos.py          # показать, что изменится
   cd backend && .venv/Scripts/python tools/link_photos.py --apply  # записать в базу
   ```

   На Linux — `.venv/bin/python`. Скрипт печатает, какому товару какой файл достанется,
   и отдельными списками — товары без снимка и файлы, которые никому не подошли. Без
   `--apply` он ничего не пишет, так что первый запуск безопасен.

Если снимки названы не кодами, а по-своему (`tomato-cherry.jpg`), скрипт всё равно
пригодится: он сопоставляет и по уже записанному в базе имени файла, то есть после
переименования файлов в прежние имена привязка восстановится сама.

## Ручной способ: одна карточка

1. Положите файл в `frontend/public/products/`, имя — латиницей в нижнем регистре, через
   дефис: `tomato-cherry.jpg`. Кириллица и пробелы ломают адрес, длина имени — до 120
   символов (ограничение поля в базе).
2. Пересоберите фронтенд: `cd frontend && npm run build`.
3. В админке → **Товари** откройте товар, впишите имя файла в поле «Зображення» и
   сохраните. Под полем сразу появится превью — если его нет, имя не совпадает или файл
   не попал в сборку.

Быстрая проверка без админки: откройте `http://<адрес прибора>/products/<имя файла>` —
браузер должен показать снимок.

## Какими должны быть снимки

| Параметр | Значение | Почему так |
| --- | --- | --- |
| Формат | JPEG, sRGB | PNG нужен только ради прозрачности, а её на карточке нет |
| Пропорции | **4:3, горизонтальные** | под такую форму сделана область фото в карточке |
| Размер | 800 × 600 … 1200 × 900 px | на развёрнутой карточке снимок занимает ≈ 630 × 510 px, меньший исходник будет мылить |
| Вес файла | до 300 КБ | на прибор грузится десяток снимков сразу; демо-файлы весят 13–30 КБ |
| Фон | однотонный светлый или белый | карточка белая, а пёстрые фоны превращают сетку в мозаику |
| Кадр | один товар по центру, отступ ~10 % со всех сторон | снимок обрезается по `cover`, и края уходят под рамку |
| Масштаб | одинаковый по всему каталогу | товар должен занимать ≈ 80 % кадра, иначе карточки выглядят разнобоем |
| Чего не должно быть | надписей, ценников, водяных знаков, коллажей | подпись и цену рисует сама карточка, вторая надпись спорит с ней |

Отдельно про обрезку: в карточке фотография заполняет свою область целиком
(`object-fit: cover`), то есть лишнее по длинной стороне срезается. Поэтому важен запас
по краям — товар, вплотную подведённый к границе кадра, на экране окажется подрезанным.

Развёрнутая карточка (когда товар выбран) растёт по высоте блока и сохраняет пропорции
обычной, так что один и тот же файл работает в обоих размерах — отдельных «крупных»
снимков не нужно.

## Если снимка нет

Оставьте поле «Зображення» пустым — карточка покажет эмодзи из поля `emoji` товара.
Это нормальный рабочий режим: пустое поле лучше чужого или неподходящего снимка.
