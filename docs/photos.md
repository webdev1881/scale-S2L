# Фотографии товаров

Демонстрационные снимки в `frontend/public/products/` — временные, они взяты с Wikimedia
Commons (лицензии перечислены в `frontend/public/products/credits.md`). Ниже — как
заменить их своими.

## Где лежат и как попадают на экран

| Что | Где |
| --- | --- |
| Файлы снимков | `frontend/public/products/` |
| Ссылка в базе | поле `image` товара — **только имя файла**, без пути |
| Адрес на экране | `/products/<имя файла>` |
| Обложка группы | фото первого товара в ней, отдельного набора картинок нет |

Прибор отдаёт снимки из собранного фронтенда (`frontend/dist/products/`), а туда они
попадают из `public/` **во время сборки**. Поэтому после добавления файлов обязательно:

```bash
cd frontend && npm run build
```

Без пересборки новый файл не появится, а карточка останется с эмодзи-заглушкой.
(Если такой порядок неудобен на работающем приборе — скажите, отдам каталог снимков
напрямую, тогда файлы будут подхватываться без сборки.)

## Порядок замены

1. Сложите свои снимки в `frontend/public/products/`, имена — латиницей в нижнем
   регистре, через дефис: `tomato-cherry.jpg`, `beef-steak.jpg`. Кириллица и пробелы в
   именах ломают адрес, длина имени — до 120 символов (ограничение поля в базе).
2. Пересоберите фронтенд: `cd frontend && npm run build`.
3. Откройте админку → **Товари**, у нужного товара впишите имя файла в поле
   «Зображення» (например `tomato-cherry.jpg`) и сохраните. Под полем сразу видно
   превью — если оно не появилось, имя не совпадает или файл не попал в сборку.
4. Ненужные демо-снимки удалите из `public/products/`, а `credits.md` очистите или
   замените своими правами на фотографии.

Быстрая проверка без админки: откройте `http://<адрес прибора>/products/<имя файла>` —
браузер должен показать снимок.

## Какими должны быть снимки

| Параметр | Значение | Почему так |
| --- | --- | --- |
| Формат | JPEG, sRGB | PNG нужен только ради прозрачности, а её на карточке нет |
| Пропорции | **4:3, горизонтальные** | под такую форму сделана область фото в карточке |
| Размер | 800 × 600 … 1200 × 900 px | на развёрнутой карточке снимок занимает ≈ 630 × 510 px, меньший исходник будет мылить |
| Вес файла | до 300 КБ | на прибор с J6412 грузится десяток снимков сразу; демо-файлы весят 13–30 КБ |
| Фон | однотонный светлый или белый | карточка белая, а пёстрые фоны превращают сетку в мозаику |
| Кадр | один товар по центру, отступ ~10 % со всех сторон | снимок обрезается по `cover`, и края уходят под рамку |
| Масштаб | одинаковый по всему каталогу | товар должен занимать ≈ 80 % кадра, иначе карточки выглядят разнобоем |
| Чего не должно быть | надписей, ценников, водяных знаков, коллажей | подпись и цену рисует сама карточка, вторая надпись спорит с ней |

Отдельно про обрезку: в карточке фотография заполняет свою область целиком
(`object-fit: cover`), то есть лишнее по длинной стороне срезается. Поэтому важен запас
по краям — товар, вплотную подведённый к границе кадра, на экране окажется подрезанным.

## Если снимка нет

Оставьте поле «Зображення» пустым — карточка покажет эмодзи из поля `emoji` товара.
Это нормальный рабочий режим: пустое поле лучше чужого или неподходящего снимка.
