# Новый прибор: от коробки до выгрузки из 1С

Пошаговая инструкция на один прибор Rongta Aurora S2. Рассчитана на то, что её
выполняет человек с ноутбуком рядом с весами, не зная проекта; на всё уходит
около часа, из них большая часть — установка пакетов на самом приборе.
Технические подробности, обновление и разбор неполадок — в `docs/deploy.md`.

## 0. Что подготовить заранее

| Что | Где взять |
| --- | --- |
| Прибор Aurora S2 с Ubuntu 24.04, клавиатура, сеть (кабель или Wi-Fi) | комплект |
| Имя прибора | по правилу ниже |
| Доступ в аккаунт Cloudflare владельца (домен `smk-retail.com`) | владелец |
| Доступ к 1С, справочник `SMK_HTTP_Настройки` | учётная служба |
| При клонировании — архив `data/` с готового прибора | см. шаг 2 |

**Имя прибора** — латиницей, без пробелов: `vesy-<магазин>-<номер>`, например
`vesy-kyiv-1`, `vesy-lviv-2`. Это имя станет и туннелем, и адресом
`vesy-kyiv-1.smk-retail.com`, и названием элемента в 1С — везде одно и то же,
чтобы через год не гадать, какой из приборов «весы 3».

## 1. Ubuntu на приборе

1. Включите прибор, войдите под пользователем, у которого есть `sudo`.
2. Подключите сеть и убедитесь, что интернет есть:
   ```bash
   ping -c 3 github.com
   ```
3. Обновите систему и поставьте git:
   ```bash
   sudo apt-get update && sudo apt-get install -y git
   ```

Белый IP, проброс портов, VPN — **не нужны**. Прибор сам выйдет наружу через
туннель (шаг 5).

## 2. Установка ПО

Два пути; выберите один.

**А. Клон готового прибора** — те же настройки, каталог, снимки и обложки
групп. Правильный путь, когда весы ставятся в ту же сеть магазинов.

На готовом приборе:
```bash
sudo tar -C /opt/s2l -czf s2l-data.tgz data
```
Перенесите `s2l-data.tgz` на новый прибор (флешкой или `scp`) и там:
```bash
git clone https://github.com/webdev1881/scale-S2L.git
tar -xzf s2l-data.tgz
sudo scale-S2L/deploy/docker/install.sh ./data
```

**Б. Чистый прибор** — пустой каталог, его заполнит выгрузка из 1С (шаг 6).
```bash
git clone https://github.com/webdev1881/scale-S2L.git
sudo scale-S2L/deploy/docker/install.sh
```

Скрипт ставит docker и chromium, заводит пользователя `s2l`, кладёт файлы в
`/opt/s2l`, тянет образ и поднимает контейнер. В конце печатает `docker compose
ps` — контейнер `s2l` должен быть `healthy` (может занять минуту).

Репозиторий после этого не нужен: `rm -rf scale-S2L`.

## 3. `.env` прибора

Файл `/opt/s2l/.env` создан из примера. Откройте его:
```bash
sudo nano /opt/s2l/.env
```
и заполните:

| Переменная | Значение |
| --- | --- |
| `S2L_HAL_BACKEND` | `real` |
| `S2L_SCALE_PORT` | `/dev/ttyS4` — встроенный RS232 Aurora S2 |
| `S2L_PRINTER_DEVICE` | `/dev/usb/lp0` |
| `S2L_IMPORT_TOKEN` | **сгенерировать**, см. ниже; свой на каждый прибор |
| `S2L_ADMIN_PASSWORD` | пароль админки; обязателен — админка будет видна из интернета |
| `CLOUDFLARE_TUNNEL_TOKEN` | пока пусто, заполнится на шаге 5 |
| `COMPOSE_PROFILES` | пока закомментирован, раскомментируется на шаге 5 |

Токен для 1С генерируется тут же:
```bash
python3 -c "import secrets; print(secrets.token_urlsafe(24))"
```
Запишите его — он понадобится в 1С (шаг 6). Метрологию (`S2L_SCALE_*_G`) не
трогайте: она общая для всех Aurora S2.

При клонировании (путь А) токен и пароль **всё равно свои**: `.env` из архива не
берётся, только `data/`.

## 4. Железо и экран

1. Перезапустите контейнер, чтобы он прочитал `.env`:
   ```bash
   cd /opt/s2l && docker compose up -d
   ```
2. Проверьте, что весы и принтер подхвачены:
   ```bash
   docker compose logs --tail 20 | grep HAL
   ```
   Должно быть `HAL: real | весы: serial | принтер: usb_raw`. Если весы
   `no_link` — плата на другом порту: `ls /dev/ttyS*`, поправьте
   `S2L_SCALE_PORT`, снова `docker compose up -d`.
3. Перезагрузите прибор: `sudo reboot`. После загрузки на экране должен быть
   киоск во весь экран. Положите что-нибудь на платформу — вес должен
   появиться в шапке.

Админка с ноутбука в той же сети: `http://<ip-прибора>:8000/admin`, логин
`admin`, пароль из `.env`.

## 5. Туннель Cloudflare — постоянный адрес

Делается на ноутбуке в браузере, в аккаунте владельца
(https://dash.cloudflare.com → Networking → Tunnels).

1. **Create Tunnel**, имя — имя прибора (`vesy-kyiv-1`), Create.
2. На странице туннеля выберите **Docker**. В показанной команде найдите
   `--token eyJ…` — скопируйте всё, что после `--token` (длинная строка,
   начинается с `eyJ`).
3. На приборе впишите её в `.env`:
   ```
   CLOUDFLARE_TUNNEL_TOKEN=eyJ…
   COMPOSE_PROFILES=tunnel
   ```
   (у `COMPOSE_PROFILES` уберите `#` в начале строки) и перезапустите:
   ```bash
   cd /opt/s2l && docker compose up -d
   ```
   Появится второй контейнер `s2l-tunnel`; в панели статус туннеля через
   полминуты станет **Healthy**.
4. В панели: туннель → вкладка **Routes** → **Add route** → **Published
   application**:
   - Subdomain: имя прибора (`vesy-kyiv-1`)
   - Domain: `smk-retail.com`
   - Service URL: `http://127.0.0.1:8000`
   
   Add route. DNS-запись Cloudflare создаст сам.
5. Проверьте с любого компьютера с интернетом:
   ```
   https://vesy-kyiv-1.smk-retail.com/health      → {"status":"ok"}
   https://vesy-kyiv-1.smk-retail.com/admin       → запрос пароля
   ```

С этого момента прибор доступен по имени откуда угодно — и для 1С, и для
админки. Ни один порт на роутере магазина открывать не надо.

## 6. 1С: настройка обмена

В справочнике `SMK_HTTP_Настройки` создайте элемент на этот прибор:

| Поле | Значение |
| --- | --- |
| Наименование | имя прибора (`vesy-kyiv-1`) |
| Тип_стр | `ВыгрузкаНаВесыLibra` |
| Сервер | `vesy-kyiv-1.smk-retail.com` — без `https://`, без `/` |
| Ресурс | `/api/catalog/1c-import` |
| SSL | Истина |
| api_key | `S2L_IMPORT_TOKEN` из `.env` прибора |
| Логин, Пароль | пусто |

В обработке «Выгрузка на весы»: выбрать эту настройку → **Проверить связь**
(в логе `{"status":"ok"}` и «Связь есть») → **Заполнить** → **Выгрузить в
весы**. В логе: «Принято N, создано N…». На приборе в этот момент показывается
экран «Оновлення», после — каталог с товарами и снимками.

Если «Проверить связь» пишет ошибку SSL — 1С 8.2 не договорилась с Cloudflare
по TLS: поставьте `SSL = Ложь`, всё остальное то же (запрос пойдёт по HTTP до
Cloudflare, дальше по туннелю). Подробности и формат обмена —
`integrations/1c/README.md`.

## 7. Настройка под магазин

В админке (`https://vesy-kyiv-1.smk-retail.com/admin` или по IP в сети):

- **Налаштування**: название магазина (печатается на этикетке), сетка карточек,
  группы или сразу товары, кнопки нижней панели, размеры клавиатуры, масштаб
  фото, цвета. Все правки видны на приборе сразу.
- **Товари → Обкладинки груп**: картинки групп и их порядок (перетаскиванием).
  Обложки переживают выгрузки из 1С и чистку.
- **Етикетка**: конструктор — заводская раскладка повторяет образец сети, тут
  можно подвинуть или убрать блок; превью и печать рисуются одним кодом.

Напечатайте пробную этикетку, положив товар на платформу и нажав карточку.

## 8. Перед сдачей

Уберите следы проверки — пробные печати и погашенные товары; каталог, снимки
и обложки остаются:

```bash
cd /opt/s2l && docker compose exec s2l python tools/clean_db.py --apply
```

(или в админке: Товари → Очистити дані → Журнал операцій).

## Контрольный список

- [ ] `/opt/s2l/.env`: `real`, порты, свой `S2L_IMPORT_TOKEN`, `S2L_ADMIN_PASSWORD`
- [ ] `docker compose ps` — `s2l` и `s2l-tunnel` `healthy`/`running`
- [ ] в логе `HAL: real | весы: serial | принтер: usb_raw`
- [ ] после `reboot` — киоск на экране, вес в шапке
- [ ] `https://<имя>.smk-retail.com/health` отвечает снаружи
- [ ] `/admin` снаружи спрашивает пароль
- [ ] элемент в `SMK_HTTP_Настройки`, «Проверить связь» — ok
- [ ] выгрузка из 1С прошла, каталог и снимки на экране
- [ ] пробная этикетка напечатана и читается сканером на кассе
- [ ] `clean_db.py --apply` перед сдачей
- [ ] записано: имя прибора, магазин, дата, кто ставил

## Если что-то не так

| Симптом | Куда смотреть |
| --- | --- |
| контейнер не стартует, «device not found» | `S2L_SCALE_PORT`/`S2L_PRINTER_DEVICE` в `.env` указывают на несуществующее устройство |
| весы `no_link` в киоске | порт платы; `ls /dev/ttyS*`, `docker compose logs` |
| туннель `Inactive` | токен в `.env` неполный, `COMPOSE_PROFILES=tunnel` закомментирован, `docker compose ps` не показывает `s2l-tunnel` |
| 1С: «Couldn't resolve host name» | в поле «Сервер» лишний `https://`, путь или пробел; DNS на сервере 1С не знает имя (`nslookup`) |
| 1С: 401 | `api_key` в 1С ≠ `S2L_IMPORT_TOKEN` на приборе |
| 1С: 503 | `S2L_IMPORT_TOKEN` на приборе пуст |
| каталог не обновился после выгрузки | в логе 1С ответ `received/updated`; на приборе `docker compose logs` — запрос `POST /api/catalog/1c-import` |
| экран чёрный после загрузки | `sudo systemctl status s2l-kiosk`, `journalctl -u s2l-kiosk` |

Обновление ПО на уже стоящем приборе — `docs/deploy.md`, «Обновление»: две
команды, данные не трогаются.
