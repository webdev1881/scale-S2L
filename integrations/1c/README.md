# Выгрузка каталога из 1С на весы

`original-Libra.bsl` — модуль формы внешней обработки 1С 8.2, которая уже работает
у заказчика. **Обработка не правится**: под неё подстроен приёмник на весах
(`backend/app/api/import_1c.py`). Что она шлёт и что весы отвечают — ниже.

## Где искать весы

1С доступна только через RDP, значит на весы она ходит снаружи — из сети сервера
1С в сеть магазина. Приборы стоят за NAT провайдера без белого IP (WAN роутера —
приватный адрес), так что проброс портов до них не доходит. Поэтому не 1С идёт
внутрь, а прибор сам держит исходящий туннель к Cloudflare, и 1С видит каждые
весы по имени вида `vesy-1.example.com` (настройка туннеля на приборе — в
`docs/deploy.md`, «Каталог из 1С»). Каждый прибор в 1С — отдельный элемент
`SMK_HTTP_Настройки`; выгрузка запускается по разу на прибор.

Для проверки без домена подходит быстрый туннель на машине разработчика:
`cloudflared tunnel --url http://127.0.0.1:8000` печатает временное имя
`*.trycloudflare.com` — оно живёт, пока запущена команда, и меняется при каждом
запуске.

## Элемент справочника `SMK_HTTP_Настройки`

| Поле | Значение |
| --- | --- |
| Тип_стр | `ВыгрузкаНаВесыLibra` (так возвращает `ТипПодключения()` в обработке) |
| Сервер | имя прибора в туннеле **без** `https://`: `vesy-1.example.com` |
| Ресурс | `/api/catalog/1c-import` |
| SSL | Истина (порт 443 подставится сам) |
| api_key | значение `S2L_IMPORT_TOKEN` из `/opt/s2l/.env` на приборе |
| Логин, Пароль | пусто — весы проверяют только `api_key` |

Если платформа 8.2 не договаривается с Cloudflare по TLS (в логе «ОШИБКА
связи: … SSL»), запасной вариант — `SSL = Ложь` с тем же именем: Cloudflare
принимает и обычный HTTP на порту 80 и заворачивает его в туннель. Для этого в
Cloudflare у домена должно быть выключено «Always Use HTTPS» (иначе 1С получит
301 вместо ответа). Токен на участке 1С → Cloudflare тогда идёт открытым текстом,
поэтому это именно запасной вариант.

Токен на приборе: `python3 -c "import secrets;print(secrets.token_urlsafe(24))"`,
вписать в `.env`, `docker compose up -d` (см. `docs/deploy.md`). Пустой токен
закрывает приём вовсе (503), неверный — 401.

## Что шлёт обработка → что делают весы

`POST <Ресурс>`, заголовок `X-API-Key: <api_key>`, тело:

```json
{
  "generated_at": "2026-09-15T18:20:00",
  "replace_images": false,
  "products": [
    {"article": 12345, "name": "Яблука Голден кг", "unit": "weight", "price": 59.9,
     "category": "Фрукти", "in_stock": true,
     "image_base64": "...", "image_format": "jpg"}
  ]
}
```

| Поле 1С | На весах |
| --- | --- |
| `article` | код товара `plu` — его покупатель набирает на весах, он же пять цифр в штрихкоде. Позиция без артикула или с артикулом длиннее пяти цифр **пропускается** и попадает в `errors[]` ответа; весь пакет из-за неё не отклоняется |
| `name` | название, до 120 символов (обработка сама обрезает) |
| `unit` | `weight` — реквизит `Весовой`, иначе `piece` |
| `price` | цена за кг или за штуку |
| `category` | группа на весах = родитель номенклатуры; пустая — группа на весах не меняется |
| `in_stock` | обработка всегда шлёт `true`; отбор «только в наличии» она делает сама, не попавшее в пакет гасится на весах |
| `image_base64` + `image_format` | снимок; кладётся новым позициям, существующим — только при `replace_images = true` |

Синхронизация полная: товар, которого нет в пакете, на весах гасится
(`active = 0`, из истории не пропадает). Пустой пакет и пакет без единого
пригодного артикула отклоняются (400) — иначе сбой выгрузки погасил бы весь
каталог. После приёма киоск перерисовывается сам (`live.notify("catalog")`).

Ответ, который обработка разбирает и пишет в лог:

```json
{"received": 3, "created": 1, "updated": 2, "deactivated": 0,
 "errors": [{"plu": 0, "name": "Без артикула", "error": "нет числового артикула"}]}
```

Кнопка «Проверить связь» — `GET /health` на том же адресе, отвечает
`{"status":"ok"|"degraded"|"starting"}`; `degraded` — служба жива, весовая плата
не на связи, выгрузке это не мешает.

## Проверка без 1С

```bash
curl -s -X POST http://<адрес>:<порт>/api/catalog/1c-import \
  -H "X-API-Key: <токен>" -H "Content-Type: application/json" \
  -d '{"products":[{"article":12345,"name":"Тест","unit":"weight","price":1}]}'
```

Помните, что это полная синхронизация: такой запрос погасит всё, кроме 12345.
