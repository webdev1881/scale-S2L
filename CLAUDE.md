# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ПО для весов самообслуживания Rongta Aurora S2: FastAPI + Vue 3 (Composition API) + Element Plus.
Паспортные данные прибора — `docs/hardware/aurora-s2.md`; экран 1366x768, НПВ 15 кг,
цена деления 2/5 г, ширина этикетки не более 56 мм.
Целевое устройство — Ubuntu 24.04 x86_64 в режиме киоска. Язык интерфейса — украинский
(переключается в админке), язык кода и комментариев — русский.

## Команды

```bash
# Бэкенд (Windows-пути; на Linux — .venv/bin/)
cd backend && .venv/Scripts/python -m uvicorn app.main:app --reload --port 8000

# Фронтенд
cd frontend && npm run dev          # киоск :5173/, админка :5173/admin.html
cd frontend && npm run build        # после сборки FastAPI сам отдаёт / и /admin
cd frontend && npm run typecheck    # vue-tsc; запускать перед сдачей изменений
```

## Слой абстракции железа — главное правило

Код вне `backend/app/hal/` **никогда** не обращается к порту, устройству или библиотеке
железа напрямую. Любой новый узел добавляется как интерфейс в `hal/base.py` плюс **две**
реализации: `fake` (симулятор) и реальный драйвер. Выбор — только в `hal/registry.py`.

Без этого разработка вне работы (весы недоступны) и автотесты становятся невозможны.

- `S2L_HAL_BACKEND=fake` — режим по умолчанию, вся разработка идёт в нём.
- Метрологические параметры (НПВ, цена деления, наименьшая навеска) живут в `.env`,
  а не в админке: это свойства прибора. Показание всегда кратно цене деления —
  вес, который прибор не может измерить, не должен попадать на этикетку.
- Эндпоинты `/api/sim/*` существуют только для `fake` и обязаны возвращать 400 на `real`.
- Протокол весовой платы подтверждён на приборе: `/dev/ttyS4`, 19200 8N1, кадр
  из 8 байт с шестью ASCII-цифрами граммов (см. `docs/hardware/aurora-s2.md`).
  Разбор кадра менять только в `SerialScale._parse_frame` — остальной код не трогать.
- Кадры выцепляются из потока по признаку, а не отрезаются вслепую по 8 байт:
  после потери байта слепое чтение склеивает половинки соседних кадров в
  правдоподобные, но неверные числа — то есть в неверную цену на этикетке.

## Темы

- Киоск живёт в двух темах, светлая по умолчанию. Админка всегда светлая.
- **Ни одного цвета в компонентах.** Палитра — токены в `shared/styles/base.css`:
  светлые на `:root`, тёмные под `[data-theme='dark']`. Захардкоженный цвет
  останется светлым при переключении и выдаст себя пятном.
- Тема вешается на `<html>`: `data-theme` включает наши токены, класс `dark` —
  переменные Element Plus, иначе диалоги и тосты останутся белыми.
- До прихода настроек применяется тема прошлого запуска из `localStorage` —
  иначе заставка успевает мигнуть чужим фоном.
- Киоск перечитывает настройки на возврате к начальному экрану: смена темы или
  языка в админке подхватывается без перезапуска. Опроса по таймеру нет.

## Локализация

- **Ни одной строки интерфейса в компонентах.** Все тексты — в `frontend/src/shared/i18n.ts`,
  оба языка (`uk`, `ru`) правятся одновременно. Язык хранится в настройках устройства,
  а не в браузере: киоск обслуживает покупателей, а не владельца ноутбука.
- Бэкенд **не** отдаёт готовые фразы об ошибках. Он возвращает коды из `app/errors.py`
  (`print.paper_out`, `scale.no_link`, …), интерфейс переводит их через `translateError`.
  Новая ошибка = код в `errors.py` + ключ в обоих словарях.
- Точка в ключе словаря — разделитель пути в vue-i18n, поэтому коды хранятся с
  подчёркиванием (`print_paper_out`), а `translateError` делает замену.
- Единственный текст, который переводит бэкенд, — надписи на этикетке
  (`app/services/i18n.py`): они впечатываются в растр, фронтенд их не видит.
- Даты и время форматируются через `localeTag()`, а не зашитым `ru-RU`.

## Этикетка

- Превью в браузере и печать используют **один и тот же растр** (`services/label.py`).
  Не добавлять отдельный путь отрисовки для превью — разъедется с бумагой.
- Текст на этикетке рисуется в битмап (Pillow), а не встроенными шрифтами принтера:
  во встроенных нет кириллицы. Штрихкод — тоже растром.
- Шаблон весового EAN-13 задаётся строкой в настройках (`P` — цифра PLU, `W` — цифра
  значения). Не зашивать формат в код: у каждой сети он свой.

## Бизнес-логика веса

Тара, стабилизация, минимальная масса и округление считаются **на бэкенде**
(`services/printing.py`). Фронтенд только отображает и блокирует кнопку. Причина —
метрологическая: расчёт, попавший в браузер, невозможно ни проверить, ни сертифицировать.

## Киоск (frontend/src/kiosk)

- Каталог двухуровневый: карточки групп -> карточки товаров. Поиск работает поперёк
  групп и сразу показывает товары. Возврат — кнопкой в шапке, а не жестом.
- Вёрстка рассчитана на экран прибора 1366x768; сетка по умолчанию 4x2. Меняя
  размеры, проверяйте именно это разрешение, а не окно ноутбука.
- Сетка каталога **не прокручивается**: страница фиксирована (`grid_cols` x `grid_rows`
  для групп, `product_grid_cols` x `product_grid_rows` для товаров — сетки разные,
  групп полтора десятка, а товаров в группе больше), лишнее уходит в пагинацию. Обрезанный наполовину ряд на киоске выглядит
  как поломка, поэтому карточка тянется по высоте ряда, а фото забирает остаток.
- Левая панель показывает вес, цену и стоимость: сумма должна быть видна до печати,
  а не только на этикетке.
- Весы стоят шапкой во всю ширину: показание нужно видеть с любого места у
  прибора, а не только стоя напротив левого края экрана. Внутри шапки всё в
  строку — в ней высота дороже ширины.
- Пустая платформа сообщением не считается: подсказка «покладіть товар» висела бы
  почти всё время и превращалась в шум. Строка состояния сохраняет высоту, чтобы
  шапка не дёргалась при появлении текста.
- Отдельной шапки нет: состояние связи и часы живут в блоке весов, за которым
  покупатель и так следит. На 768 px строка ради трёх слов не окупается.
- Размеры подписей и доля высоты под фотографию задаются в админке и приезжают
  в вёрстку CSS-переменными на корне киоска (`--ui-*`). Экран прибора стоит от
  покупателя дальше, чем монитор от разработчика, поэтому размер подбирается
  на месте. Доля фото — именно `flex: 0 0`, а не остаток: иначе крупная подпись
  съедает фотографию и настройка перестаёт означать обещанное.
- В карточке товара код лежит поверх фотографии без подложки, название слева,
  цена справа в той же строке: взгляд идёт от «что» к «сколько», а код нужен
  только тем, кто набирает его на клавиатуре.
- Подпись карточки (и товара, и группы) — плашка во всю текстовую часть карточки,
  а не полоса под текстом: так подпись читается как отдельная панель. Плашка
  всегда во всю ширину карточки; в настройках — её высота и цвет. Цвет текста не
  настраивается, а выводится из яркости заливки, иначе одного неудачного выбора
  хватит, чтобы подпись пропала.
- Цветом плашки обведены и сами карточки (рамка 1 px), и обе кнопки поиска —
  «ПОШУК товару» внизу и «за Кодом» в строке поиска: всё, что относится к
  каталогу, красится одним цветом из настроек. Зелёный остаётся у печати и у
  перемещения по каталогу («Усі групи», стрелки пейджера).
- Кнопка набора кода стоит на тени и вдавливается, как соседняя «Усі групи»;
  включённое состояние — та же вдавленность, а не другой цвет: панель цифр на
  экране и так видна, а смена цвета на произвольной заливке из настроек читалась
  бы хуже.
- Доля высоты под фото — желаемая: плашка не бывает ниже двух строк подписи и
  ниже доли, заданной в настройках, и при крупном шрифте фотография уступает.
  Нечитаемая подпись делает карточку бесполезной, а уменьшенное фото — нет.
  Две строки — не запас: название клампится именно в две, и плашка ростом в
  полторы срезает вторую посередине букв. Высота плашки следует за размером
  подписи, поэтому уменьшить её можно тем же ползунком, что и шрифт.
- Обрезка названия по строкам живёт на вложенном элементе: у flex-элемента
  браузер приводит `display` к `flow-root`, и `-webkit-line-clamp` не работает.
- Стрелки пейджера выглядят как кнопка «Усі групи»: обе перемещают покупателя по
  каталогу, и разный вид читался бы как разное назначение.
- Возврат «Усі групи» стоит в строке поиска, между полем и набором кода: все три
  кнопки про одно и то же — как покупатель ищет товар. Стрелки у надписи нет,
  она и так говорит, куда ведёт. Строка сохраняет высоту и на верхнем уровне,
  где кнопки возврата нет, иначе карточки меняли бы размер между экранами.
- Заголовок каталога и поле поиска стоят в одну строку: слева от заголовка всё
  равно пусто, а ряду карточек эта высота нужнее. Поиск при этом прижат к весам
  и уведён подальше от кнопки, которая его открывает.
- Заголовок в блоке каталога показывается только там, где что-то сообщает: название
  открытой группы и «результаты поиска». Над сеткой групп подписи нет — карточки
  говорят сами за себя.
- Стартовая заставка (`components/SplashScreen.vue`) вместо спиннера: пиксели
  слетаются в надпись SMK. Точки берутся из растра текста, поэтому надпись
  подстраивается под любой экран. При `prefers-reduced-motion` анимация пропускается.
- Кадр заставки пишется прямо в `ImageData`, а не тысячами `fillRect`: на J6412
  вызовы канвы упираются в CPU уже на нескольких тысячах частиц, а запись в буфер
  стоит одинаково при любом их количестве (замер: 13 тыс. частиц — 2.4 мс/кадр).
  Если на приборе кадр всё же не укладывается в бюджет, крутить `MIN_STEP`
  (шаг сетки точек), а не число частиц: плотность упирается именно в него.
- Пиксели — приём сборки, а не конечный вид: кадр перетекает в тот же текст,
  нарисованный шрифтом со сглаживанием. Переход перекрывает хвост влёта и
  заканчивается ровно в момент посадки последних частиц — иначе зритель успевает
  увидеть готовую надпись из квадратов, и она читается как низкое разрешение экрана.
- Сторона точки равна шагу сетки, а позиция округляется, а не усекается. Иначе
  зерно рассыпается в дизеринг (точка мельче шага) или покрывается крапиной
  (погрешность float уводит часть точек на пиксель).
- Перелив по надписи — выборка из таблицы «оттенок × прозрачность», индекс считается
  от координаты и времени. Оттенки берутся вокруг `#409EFF` Element Plus; светлые
  токены (`#79bbff`, `#a0cfff`) в заливку не годятся — на белом выцветают.
- Тач-экран без мыши: цели касания ≥ 64 px, никаких состояний `:hover`.
- Страницы листаются свайпом наравне с пейджером и идут **лентой**: соседняя
  страница подставляется вплотную и едет вместе с текущей один в один за пальцем,
  а после отпускания лента доезжает до места. Сдвиг с сопротивлением и подменой
  страницы «на месте» ощущался рывком: палец вёл одно, а на экране в конце
  оказывалось другое. На краю каталога подставлять нечего, там лента почти не
  поддаётся — это и есть ответ «дальше ничего нет».
- Листание засчитывается по длине (четверть ширины, но не больше 200 px — на
  широком экране четверть длиннее удобного движения кистью) либо по скорости
  короткого броска. Доводка идёт в ту же сторону, куда вели: возврат почти
  ушедшей страницы читался бы как отказ прибора листать.
- Подмена страницы происходит в конце доводки, одним кадром: соседняя уже стоит
  ровно там, где окажется новая текущая, поэтому подмены не видно.
- Под пальцем лента двигается **в обход Vue**: сдвиг пишется прямо в стиль трёх
  полос (`ribbonPrev`/`ribbonCurrent`/`ribbonNext`). Через реактивное состояние
  каждое движение пальца перерисовывало бы весь киоск вместе с сетками и весами —
  лента дёргалась ровно там, где обязана быть гладкой.
- Соседние страницы монтируются на **касании**, а не на первом движении: собрать
  восемь карточек с фотографиями посреди жеста — это пропущенный кадр ровно там,
  где палец пошёл. На касании та же работа незаметна.
- Полосы лежат в одной ячейке `.grid-slot`, боковые сдвинуты на свою ширину
  через CSS (до первого движения писать в стиль некому), а сетки внутри полосы —
  снова в одной ячейке, иначе переход между уровнями выстроил бы их в два ряда.
- Жест забирается у браузера (`touch-action: pan-y` на слоте сетки), иначе он
  уходит под его собственную навигацию вместе с `pointercancel` посреди свайпа.
  Захват указателя берётся только после того, как палец действительно поехал:
  захват на самом касании отнимает у карточки `click`, и обычный тап перестаёт
  открывать товар.
- После любой протяжки выбор карточки гасится вручную: браузер шлёт `click` даже
  после сотни пикселей, а палец к этому моменту стоит уже над чужой карточкой.
- Смена уровня каталога анимируется наложением: уходящая и приходящая сетки лежат
  в одной ячейке. Последовательный режим (`mode="out-in"`) требует, чтобы уход
  обязательно завершился, и любая заминка оставила бы каталог пустым.
- Листание анимируется страницей целиком: номер страницы входит в ключ сетки,
  уходящая уезжает в сторону движения, приходящая приезжает с противоположной.
  Переход достаётся только кнопкам пейджера: свайп двигает ленту сам, и
  добавленный поверх сдвиг читался бы как второе, чужое движение. Свайп меняет
  страницу без перехода — имя `none`, у которого одно-единственное правило:
  `display: none` на уходящей сетке. Vue держит её в DOM до следующего кадра, и на
  более короткой новой странице старые карточки просвечивали в пустых ячейках —
  блик ровно в конце жеста.
  Карточками листать нельзя: на время перехода в сетке оказывается вдвое больше
  карточек, ряды пересобираются и кадр дёргается — а вертикальный влёт карточек
  ещё и спорит с горизонтальным жестом.
- Смена набора карточек анимируется самими карточками через `TransitionGroup`:
  он даёт перестановку соседей, а лесенка задержек (`--i`) превращает подмену
  списка в проявление. Лишние карточки на время перехода уходят в неявные ряды
  нулевой высоты, чтобы не сжимать страницу.
- Спокойный режим включается и на время смены самой сетки — столбцы под выехавшей
  панелью, ряды под клавиатурой. Это не изменение списка, а изменение раскладки:
  влёт карточек снизу со ступенчатой задержкой поверх меняющейся ширины читается
  как рывок в конце анимации. По той же причине ширина каталога под панель
  меняется одним шагом, а не едет 0.22 с вместе с карточками.
- Но **пока набирают** код или название, перестановка выключена (класс `calm`):
  список пересобирается на каждой цифре, карточки не успевают доехать до новых
  мест и на следующем нажатии едут заново — особенно заметно, когда их осталось
  мало и ехать далеко. В наборе карточки не двигаются, новые просто проявляются.
  Отсутствие перехода у `.card-move` — не украшение: Vue проверяет, есть ли у
  класса перестановки переход, и без него пропускает FLIP целиком, не трогая
  позиции. Уходящая карточка при этом получает `display: none`, иначе оставшиеся
  встают вокруг неё и через кадр перескакивают.
  При `prefers-reduced-motion` все переходы отключаются.
- Прокручивается **только** сетка товаров. Элементу внутри grid-трека нужен
  `min-height: 0`, иначе он растёт по контенту и перекрывает соседей.
- Экранные клавиатуры свои, системная (squeekboard/onboard) не используется:
  `Numpad.vue` — цифры для PLU, `Keyboard.vue` — буквы и цифры для поиска,
  открывается по фокусу в поле поиска. Раскладка идёт за языком интерфейса.
- Клавиатура поиска выезжает снизу **внутри колонки каталога** (`position: absolute`
  в `.main`), а не поверх всего экрана: `--s2l-kb-height` задаёт её высоту и нижний
  отступ этой же колонки. Весы остаются видны целиком, сжимается только сетка.
- Цифровой блок, наоборот, выезжает справа **поверх карточек**: он узкий, и
  поджимать ради него весь каталог по высоте незачем — ряды, пейджер и итоговая
  панель остаются на месте. Но сетка на это время сужается ровно до его левого
  края и ограничивается двумя столбцами: карточка, срезанная панелью пополам,
  читается как поломка, а не как перекрытие. Ширина панели живёт в
  `--s2l-pad-width` — она же уходит в отступ каталога. Перекрытие делается обёрткой
  `.catalog-area` вокруг сетки: размещение блока в самой сетке `.main` уводило его
  в неявную колонку за край экрана.
- Пока открыта клавиатура поиска, сетка ограничена одним рядом — иначе карточки
  сжимаются до нечитаемых полосок. Одного ряда мало: на 1366x768 клавиатура
  (292 px) вместе с итоговой панелью (114 px) оставляют ряду 50 px, поэтому на
  время набора итоговая панель убирается — ряд получает 164 px, и карточка снова
  читается. Цифровой блок ни рядов, ни панели не трогает: он ничего не поджимает.
- Клавиши обеих панелей шлют события (`key`, `backspace`, `clear`), а строку
  меняет владелец состояния. Если читать текущее значение из пропа, два быстрых нажатия в одном
  тике прочитают одно и то же старое значение и символ потеряется.
- Поиск по коду динамический: каждая цифра сразу сужает каталог, как и буквы в
  поиске по названию, — кнопка «Знайти» только подтверждает выбор (точное
  совпадение либо единственный оставшийся товар). Набранный код показывается в
  заголовке каталога: строки с ним на экране нет, и без подписи отфильтрованный
  каталог выглядел бы поредевшим сам по себе.
- Выбор товара из результатов по коду проваливает в его группу и снимает фильтр:
  иначе в каталоге осталась бы одна карточка без видимой причины.
- Касание мимо цифрового блока убирает его так же, как касание мимо клавиатуры:
  касание результатов оставляет найденное, всё остальное возвращает экран к
  состоянию до набора.
- Касание мимо поля и клавиатуры отменяет поиск: экран возвращается к состоянию
  до набора (строка, открытая группа, страница — снимок берётся при открытии
  клавиатуры). Касание самих результатов и пейджера поиском не считается
  отказом — оно лишь закрывает клавиатуру. «Готово» тоже сохраняет результаты.
  Класс, по которому распознаются результаты, обязан существовать в разметке:
  с устаревшим `.catalog` касание карточки откатывало экран к состоянию до
  набора, и палец попадал уже по другому товару.
- Причина, по которой печать недоступна, показывается прямо на кнопке, а не тостом.
  Исключение — «товар не выбран»: вместо мёртвой подписи там стоит кнопка поиска,
  потому что это и есть следующий шаг покупателя. Она открывает клавиатуру и
  ставит фокус в поле одним нажатием.

## Настройки устройства

Живут в `backend/data/settings.json`, а не в БД: их переносят на новый прибор,
кладут в резервную копию и правят руками, когда админка недоступна — запирать их
в SQLite вместе с товарами незачем. Запись атомарна (временный файл + замена):
обесточивание в момент сохранения иначе оставило бы обрезанный JSON, и прибор
поднялся бы на значениях по умолчанию.

Размеры подписей и доля высоты под фото — оттуда же, в вёрстку приезжают
CSS-переменными `--ui-*` на корне киоска.

## Пути и конфигурация

Расположение данных не должно зависеть от того, откуда запущен процесс. Уже дважды
ловили одно и то же (issues #1 и #2): относительный путь резолвится от рабочего
каталога, а uvicorn запускают то из `backend/`, то из корня репозитория, то из
systemd. Поэтому `env_file` абсолютный, а относительный путь в `S2L_DB_URL`
привязывается к каталогу `backend/`. Каталог под базу создаём сами: SQLite этого
не делает и падает с невнятным «unable to open database file».

Любой новый путь в конфиге проверяйте запуском из корня репозитория, а не только
из `backend/`.

## Прочее

- Поиск товаров по названию фильтруется в Python, а не в SQL: `LIKE` в SQLite
  не понимает регистра кириллицы.
- Товары удаляются мягко (`active = 0`) — на них ссылается журнал операций.
- Миграций пока нет, схема создаётся через `create_all`. При первом изменении моделей
  на устройстве с данными — вводить Alembic.
- Админка использует хэш-роутинг: одинаково работает и на `/admin.html`, и на `/admin`.
- Фото товаров лежат в `frontend/public/products/`, в БД хранится только имя файла.
  Обложка группы — фото первого товара в ней, отдельного набора картинок нет.
  Демо-снимки взяты с Wikimedia Commons, лицензии — в `products/credits.md`.
- Классы в разных компонентах не должны совпадать по именам: scoped-стили киоска
  уже ловили коллизию `.right` (шапка против колонки каталога).
